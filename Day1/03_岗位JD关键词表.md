## 二、岗位匹配等级

- **A：高匹配**：核心技能中至少 60% 有真实项目证据，且能讲清实现细节；优先投递并定制材料。
- **B：可竞争**：有相邻经验，1–2 个关键点需要快速补齐；投递后加入待补清单。
- **C：探索性**：岗位主要偏基础模型训练、分布式训练或与当前主线差异较大；只在岗位吸引力较高时投递。

匹配时不要只按技术名词数量判断，还要检查：

1. 是否做过相同或相邻业务场景。
2. 是否有可说明的个人职责。
3. 是否能解释该技术为什么被使用。
4. 是否能回答上线、评估、安全和失败处理问题。

## 四、JD 分析方法

### 第一步：提取关键词

将 JD 中的要求分为五类：

| 类别 | 关注内容 | 示例 |
| --- | --- | --- |
| 业务方向 | 公司用 AI 解决什么问题 | 知识库、研发效能、客服、数据分析、代码生成 |
| 模型能力 | 需要理解或使用什么模型能力 | LLM、Embedding、Rerank、Function Calling、多模态 |
| Agent 架构 | 需要构建什么流程 | Workflow、ReAct、Plan-and-Execute、Multi-Agent、MCP |
| 工程能力 | 需要怎样交付 | Python、FastAPI、数据库、Docker、异步、监控 |
| 协作能力 | 需要怎样工作 | 需求分析、跨团队协作、文档、测试、Owner 意识 |

### 第二步：建立证据

每个关键词都填写一条证据，使用以下格式：

> **关键词**：Hybrid RAG  
> **证据**：论文引用查证智能体中完成 BM25 + FAISS + Rerank 检索链路，并使用人工标注集评估 Recall@k、证据覆盖率和判定准确率。  
> **熟练度**：能够讲清架构和选型，需继续补齐线上评估与调优细节。

### 第三步：确定讲述顺序

- **Agent 岗**：AI Coding Harness → 成果评审 Agent → 质量管理体系 Agent。
- **RAG / 知识库岗**：论文引用查证 → 质量管理体系 Agent → 成果评审 Agent。
- **AI 全栈岗**：质量管理 Agent → FastAPI/数据库工程化 → Vue/传统全栈。
- **算法/视觉岗**：红外动作识别 → 论文/人工智能课程 → Agent 工程作为应用补充。

### 第四步：定制自我介绍

每份重点 JD 只修改三处：

1. 1 分钟版中第二个项目的选择。
2. 3 分钟版中项目的展开顺序。
3. 结尾处的岗位匹配句。

不需要为每家公司重写整篇自我介绍。

## 六、每天更新规则

之后每份学习笔记只保留一份可学习内容，统一遵循以下格式：

1. **核心概念**：给出准确、简洁的解释。
2. **简历关联**：说明与你哪个项目相关。
3. **面试回答**：整理成可以直接口述的版本。
4. **追问与边界**：列出容易被继续追问的地方。
5. **验收清单**：完成后可以自测是否掌握。

不再使用“初稿”“终稿”“草稿”等版本称呼。后续有修改时，直接在同一份文件中更新内容。
