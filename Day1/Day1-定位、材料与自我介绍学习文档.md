## 四、经历价值提炼卡

每张卡控制在 20—30 秒，按“场景 → 我做的关键动作 → 业务价值 → 边界”口述。

### 赛目科技 AI 应用开发实习

> 我在企业质量管理和代码评审场景中开发 Agent。我的重点不是让模型自由回答，而是用 LangGraph、受控工具、RAG、证据校验和人工确认，把模型能力放进可审计的业务流程。简历没有统一的线上准确率指标，所以我会说明证据链、降级和任务状态等可验证设计，而不虚构效果数据。

### 质量管理体系 Agent

> 质量管理 Agent 接入禅道 BUG、GitLab Commit、飞书需求文档和质量体系文件。我设计了结构化指标计算与质量体系 RAG 的边界：BUG 严重等级、功能分布等事实通过指标工具计算，checklist 由检索提供依据，LLM 只负责在事实和依据之上归纳，从而降低无依据判断风险。

### 分公司内网 GitLab 数据接入

> 中心系统不能主动访问分公司内网的 GitLab 时，我实现 Edge 端主动同步：SQLite Outbox 保存待同步数据，游标定位增量，中心按批次幂等接收，并结合多实例数据隔离和 Docker 化交付，将 Commit 安全接入中心质量看板。这个经历说明我能处理 Agent 之外的网络边界和数据可靠传递问题，但不会夸大为已有实时性或吞吐指标。

### 功能开发成果评审 Agent

> 我设计并实现了面向 GitLab 代码仓库的证据驱动评审流程。9 节点 LangGraph 工作流把清单加载、仓库快照、事实提取、证据组装和逐项裁决串联起来；每项结论关联路径、行号和快照 SHA，无证据或引用非法时降级为“无法确认”，再由人工确认归档。

### 最小 AI Coding Harness

> 我为企业 Agent MVP 自建面向 Claude Code/Codex 的受控 AI 开发框架，把架构约束、接口契约、测试策略、稳定决策和任务状态沉淀为工程上下文，并设计“业务建模、任务单人工确认、AI 编码与测试、人审验收、归档续接”的闭环。它的目标不是替代工程师，而是约束 AI 的上下文和审批边界。

### 论文引用查证智能体

> 我构建了从论文 PDF 解析到证据检索、引用合理性判断和结构化输出的 RAG 链路：GROBID 解析 TEI XML，BM25、FAISS 和 Rerank 组成 Hybrid RAG，人工标注集评估 Recall@k、证据覆盖率和判定准确率。证据不足时系统返回“无法确认”，避免用流畅回答替代可靠结论。

### 轻舟货运飞船前端与传统全栈经历

> 我在轻舟货运飞船前端实现遥测、报警、货物状态和语音事件的周期刷新，通过事件去重、路由和状态管理保证页面一致性，并在用户交互期间暂停和恢复刷新，避免实时数据回填覆盖操作。我也参与过 Vue、PHP/MySQL、支付、电子签名和公众号推送等全栈交付，因此能从后端接口到前端交互理解 AI 应用的完整闭环。

### 红外动作识别课题

> 我基于 NTU RGB-D 数据集，用 ResNet-18 加 LSTM 构建非 Transformer 的红外动作识别基线，并设计两层红外增强、Uniform Sampling 和轻量 Temporal Attention。在官方 Cross-Subject 协议下，均匀采样方案达到 96.55% Accuracy 和 0.9934 AUC，综合配置达到 0.9424 F1；这些指标对应不同配置，不能简单横向比较谁“更高”。

## 五、简历事实边界

以下表述可以直接使用，也同时约束面试中的夸大风险。

1. 成果评审 Agent 的简历事实是“设计并实现 9 节点工作流”和“设计任务状态机”；不把状态数量说成未经新版简历确认的固定数字。
2. 论文引用查证的简历事实包括 Hybrid RAG、BM25、FAISS、Rerank、人工标注集和三项评估指标；不补充未记录的模型名称、数据规模或线上指标。
3. Edge 同步的简历事实包括 SQLite Outbox、游标增量、批次幂等、多实例隔离和 Docker 化交付；不把它说成“零丢失”“实时同步”或“高可用”结果。
4. 轻舟前端写的是周期性刷新；可以讨论轮询与 WebSocket 的选型，但不能说简历项目已使用 WebSocket。
5. 第三方支付、电子签名和公众号推送属于全栈经历中的已实现业务功能；没有简历依据时，不补充具体支付渠道、验签算法、并发量或故障指标。
6. 面对团队协作部分，按简历用“参与”“负责其中的”“设计并实现”准确区分，不把团队成果都说成个人独立完成。

## 六、练习方法与验收标准

### 口述顺序

1. 先脱稿讲 30 秒开场版，再使用 `01_自我介绍.md` 中的 1 分钟、3 分钟和 5 分钟稿。
2. 接着讲 `02_行为面试题库.md` 的第 5、13、16、17 题，覆盖代码评审、Edge 同步、RAG 和前端交互。
3. 最后从 `03_岗位JD关键词表.md` 选择与目标岗位最相关的 3 个关键词，各用 30 秒讲清定义、项目动作、选型理由和风险边界。

### 达标判断

- 1 分钟介绍能够说出身份、方向、两个项目证据和“证据驱动、可靠性约束、工程化交付”中的至少两个标签。
- 3 分钟介绍按“经历演进 → 两个核心项目 → 工程能力 → 岗位匹配”展开；被打断时能从当前项目自然进入追问。
- 5 分钟项目介绍说明背景、约束、方案、个人动作、技术取舍、风险控制和后续改进，不报出简历外的数字。
- 每个 STAR 故事中，S/T 简洁，A 明确是“我做了什么”，R 只使用简历支持的交付结果、验证方式或风险控制。
- 知道不确定的细节时，直接说明“当前简历能确认的是……”，而不是猜测实现或指标。

Day 1 的学习资料已形成直接背诵版本；实际口述和录音由本人完成，但无需在文档中虚构为已完成记录。
