# Day 6：30 分钟复习版——后端、数据库与工程化

> **目标**：只记一条工程主线：接口先校验，长任务有状态，外部调用可控，数据可追溯，失败能恢复。

## 0–5 分钟：90 秒工程主线

> 我的 Agent 项目里，工程重点不是把接口写出来，而是让任务在失败和重试下仍可解释。请求先经过 FastAPI/Pydantic、业务和权限校验；长耗时评审创建后返回 task ID，后台执行持久化状态、阶段、进度和心跳；幂等键避免重复创建，取消在安全检查点协作式处理，超时和重启中断有错误码和审计，重试创建关联的新任务。跨网 GitLab 接入则由 Edge 主动同步，用 SQLite Outbox 保存待发数据、游标定位增量、中心批次幂等去重，并通过隔离和 Docker 化交付控制部署边界。

**事实边界**：已确认任务状态、进度、取消/重试/中断、有界并发、Edge Outbox/游标/幂等/Docker；未确认消息队列、WebSocket、完整 Trace、Redis 具体策略和高并发压测数据。

## 5–12 分钟：两张白板图

```text
POST /tasks + idempotency_key → task_id
queued → validating → collecting → evaluating → assembling → pending_review
活动状态 → cancel_requested → canceled

```

```text

                                                ↓
                                         幂等去重/持久化
                                                ↓
                                       成功确认或保留重试
```

### 三句必说

1. “`async` 适合 I/O，不适合把 CPU/阻塞长任务直接塞进事件循环。”
2. “幂等键防重复创建，业务幂等防重复处理；消息队列不能替代这两者。”
3. “Outbox、游标、中心幂等分别解决留存、范围和重复，不承诺恰好一次。”

## 12–20 分钟：8 个必答题

### 1. `async` 一定更快吗？

> 不一定；I/O 等待可受益，CPU 密集或阻塞调用会堵塞事件循环。

### 2. 如何幂等创建任务？

> `idempotency_key` + 服务端唯一约束/原子查找创建，重复请求返回同一任务。

### 3. 长任务如何取消和恢复？

> `cancel_requested` + 安全检查点；重启遗留标 `interrupted`；重试新建任务并关联旧任务。

### 4. 索引何时失效？

> 函数/隐式转换、前导模糊、联合索引不满足最左匹配、低选择性等；最终看执行计划。

### 5. Redis 与 DB 不一致怎么办？

> 明确 DB 为事实源，选择更新后删缓存等策略并接受/控制短暂不一致；具体实现不虚构。

### 6. Docker 和数据卷分别解决什么？

> Docker 固化环境；volume 持久化 Outbox 等运行数据，避免容器重建丢失。

### 7. 轮询、WebSocket、消息队列怎么选？

> 轮询简单查状态，WebSocket 做实时推送，队列做削峰解耦；都不替代任务状态和业务幂等。

### 8. 日志、Trace、Task ID 的区别？

> 日志记事件，Trace 串调用链，Task ID 管长任务生命周期；当前只确认任务/审计/日志事实。
