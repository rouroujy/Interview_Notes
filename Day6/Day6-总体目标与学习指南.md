## 一、当天在十天计划中的位置

Day 2–Day 5 已解决项目主线、RAG、LLM、Prompt 和 Agent 工作流。Day 6 补齐 AI 应用/AI 全栈岗位最常追问的工程底座：接口如何承接任务、数据如何一致、长任务如何查询和取消、缓存与容器如何使用、同步如何在故障下恢复。

当天要形成一条工程叙事：

> 请求进入 FastAPI → Pydantic/业务/权限校验 → 服务与数据库事务 → 后台任务/状态查询 → 日志与审计 → 失败、重试、取消或恢复。

## 三、事实边界

### 可直接讲的实现事实

- FastAPI 应用在生命周期阶段处理评审遗留活动任务的中断标记；路由层提供评审任务创建、查询、取消、确认、重试等接口。
- SQLAlchemy 会话在任务/服务调用中显式使用，成功提交、异常回滚或记录失败状态。
- 代码评审任务创建支持 `idempotency_key`；重试创建新任务并关联原任务；任务状态、进度、心跳和审计可查询。
- 评审任务通过有界并发、请求 timeout、阶段 deadline 与协作式取消控制长任务风险。
- Edge 同步采用本地 Outbox、游标增量、中心批次幂等接收；简历确认多实例隔离与 Docker 化交付。

### 不能扩展为既有事实

- 不说已实现分布式队列、WebSocket、Kafka/RabbitMQ、K8s、完整链路追踪、指标告警、全链路压测或高并发容量数据。
- 不说实现“恰好一次”投递；当前安全说法是**至少一次投递 + 中心幂等处理**。
- Redis 仅按论文项目的“使用 Redis 缓存”讲；具体缓存 key、TTL、集群、分布式锁和一致性实现未核实。
