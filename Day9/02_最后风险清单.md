## 一、P0：必须在面试前修复

| 风险项 | 为什么高风险 | 安全口径 | 修复动作 | 完成 |
| --- | --- | --- | --- | --- |
| 90 秒自我介绍无法按岗位切换 | 开场决定后续追问方向 | Agent 岗优先 AI Coding Harness / 成果评审；全栈岗补轻舟；研究岗补红外课题 | 分别录音 3 次，每次不超过 90 秒 | [ ] |
| 成果评审 Agent 的个人职责不清 | 易把团队成果说成自己独立完成 | 说“我设计并实现/参与的具体模块”，并说明人工确认、只读 Token、源码不落库等边界 | 用简历逐条核对动词和职责 | [ ] |
| 质量 Agent 的 Edge 同步讲不清 | 跨网、可靠性、幂等是高频追问 | Edge 内网侧主动同步；Outbox 持久化待发、游标做增量、中心按批次幂等；至少一次投递，不承诺恰好一次 | 画一次数据流并口述 2 分钟 | [ ] |
| “证据驱动”只会喊口号 | Agent 可信性核心追问 | 结论关联路径、行号、快照 SHA；校验证据索引；无证据/非法引用降级“无法确认” | 对成果评审和论文项目各举一例 | [ ] |
| 长任务状态机说不全 | 易暴露工程细节薄弱 | 创建、执行、待人工确认、取消、失败、中断；幂等创建、协作式取消、遗留任务标 interrupted | 不看资料画状态转移 | [ ] |

| 红外实验指标混比 | 指标和实验协议易被深挖 | 96.55% Accuracy、0.9934 AUC 属于均匀采样方案；0.9424 F1 属于综合配置，不能跨配置直接比“谁更好” | 解释指标、协议和可比性 | [ ] |

## 二、P1：面试中必须主动设边界

| 容易被误说的内容 | 应该怎么说 | 不要怎么说 |
| --- | --- | --- |
| 消息队列 / 分布式 worker | 评审任务当前使用后台线程；如需扩展可考虑队列和 worker，并先补幂等、状态和取消设计 | “我们的任务已经跑在消息队列集群上” |
| WebSocket | 能解释适用场景和工程代价；轻舟已确认的是周期刷新 | “轻舟通过 WebSocket 实时推送” |
| K8s / 高并发压测 | 当前有 Docker、有界并发、超时和资源限制；生产容量要用压测与观测验证 | “系统已经支撑高并发生产集群” |
| 数据库实现细节 | 简历确认 MySQL、SQLAlchemy、Alembic；表、索引、慢 SQL 指标需看代码再答 | 编造表规模、索引或 QPS |
| Redis 缓存细节 | 论文项目确认使用 Redis；适合解析/检索等可重建中间结果，key/TTL/失效实现待核实 | 编造缓存命中率、TTL 或双写策略 |
| RAG 指标 | 论文项目确认人工标注集、Recall@k、证据覆盖率和判定准确率 | 补充没有记录的分数 |
| 模型训练细节 | 已确认数据集、协议、基线、改进和列出指标；超参数、硬件、训练轮数待查 | 临场猜 batch size、学习率、GPU 型号 |
| 第三方支付/电子签名 | 可以讲验签、幂等、对账的一般方案；旧全栈经历具体实现以实际为准 | 说出未核实的支付渠道、回调协议或资金规模 |
| 团队/个人边界 | 用“我负责/我参与/团队完成”准确归属 | 用“我一个人从 0 到 1 做完全部系统” |

## 三、P2：按 JD 定向补齐，不抢占主线

| JD 关键词 | 复习入口 | 安全口径 |
| --- | --- | --- |

## 四、答不出时的四句兜底

> 这个具体实现参数我现在不能确认，不想凭记忆补全。它要解决的核心问题是……。结合我已确认的项目事实，我做的是……；如果继续排查，我会先看……，再通过……验证。当前我能明确的风险或边界是……。

**禁用表达**： “应该是”“大概”“我们肯定”“效果很好”“所有情况都能”“我一个人全做了”。
