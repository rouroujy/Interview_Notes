## 二、当天能力目标

完成后，你应当能够：

- 在无资料、不中断的条件下，按“结论 → 依据/过程 → 风险与边界”回答问题。
- 每题使用 `可稳定回答`、`回答模糊`、`不会`、`表述有风险` 之一准确标注现状，而不是把“能看懂资料”当成“能回答”。
- 将低质量答案完成最小闭环：查对应材料 → 写三到六句简答 → 关联真实项目 → 再次口述并重评。
- 面对不了解的细节，清楚区分已实现事实、通用设计思路和待核对项，给出可执行的排查路径。
- 在不同岗位中切换项目顺序，而不把团队能力、通用方案或尚未证实的指标说成个人事实。

## 三、统一作答协议

### 1. 每题的 60–120 秒结构

1. **先给结论**：直接回答判断、方案或选择，不重复题目。
2. **再给项目依据或机制**：说明在哪个项目中如何体现；没有项目事实时明确说“这是通用设计思路”。
3. **最后给边界**：说清风险、替代方案，或哪些细节需要以代码/记录核对。

示例：

> 我会优先用稳定业务 ID 做事件去重，因为前端周期刷新时同一报警可能重复到达。轻舟项目简历确认有报警和语音事件周期刷新、事件去重及路由联动；具体去重键和时间窗口要以实现为准。如果没有稳定 ID，才结合业务字段和时间窗口，并评估误去重风险。

### 2. 不会时的安全回答

> 这个具体参数/实现细节我现在不能确认，不想猜。我的理解是它要解决……；我会先检查……，再通过……验证。回到我的项目，已确认事实是……，所以我当时能确定的边界是……。

不要用“我忘了”“应该是”“可能用了”结束回答；也不要为了完整而编造配置、压测数据、线上规模或个人职责。

### 3. 评分标准

| 维度 | 2 分 | 1 分 | 0 分 |
| --- | --- | --- | --- |
| 结论 | 开头直接、判断明确 | 有结论但铺垫过长 | 没有直接回答 |
| 事实 | 真实项目和职责准确 | 只讲通用概念 | 编造或混淆项目 |
| 技术 | 能说明原因、替代和风险 | 只有名词 | 原理错误或答非所问 |
| 结构 | 连贯、可追问 | 略跳跃 | 逻辑散乱 |
| 边界 | 主动说明未知与验证方法 | 被追问才承认 | 过度承诺 |

单题满分 10 分：`8–10` 为可稳定回答，`5–7` 为回答模糊，`0–4` 为不会；即使得分高，只要虚构事实或越权表述，也标为 `表述有风险`。

## 五、事实边界总提醒

- 质量管理体系 Agent、成果评审 Agent 和 AI Coding Harness 是当前实习中的项目；必须区分“我设计/实现”的内容与团队完成的系统能力。
- 论文引用查证项目确认有 Hybrid RAG、人工标注集、Recall@k、证据覆盖率和判定准确率，但没有已确认的具体分数，不能临场补数。
- 轻舟项目技术栈是 Vue3 / Vue Router / Vuex / Axios / ECharts / Ant Design Vue；当前企业平台的 React 条件轮询只能作为独立工程补充。
- 成果评审 Agent 确认有后台线程、有界并发、状态机、取消/重试和重启中断处理；不能说已经使用消息队列、WebSocket、K8s、分布式 worker 或完成高并发压测。
- 红外动作识别确认使用 NTU RGB-D、ResNet-18 + LSTM、Cross-Subject、两层红外增强、Uniform Sampling 和轻量 Temporal Attention；没有实验记录的超参数、硬件、训练轮数和类别表现不猜测。
