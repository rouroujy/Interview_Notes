# Day 9：30 分钟复习版——全真模拟与问题修复

> **使用场景**：面试前或模拟前快速拉起主线。不要在这 30 分钟临时扩展新知识；只检查开场、必答题、事实边界和已暴露的问题。

---

## 0–5 分钟：三段开场

### Agent / AI Coding 版

> 我当前的重点是把 Agent 做成受控、可追溯的业务流程：质量 Agent 用工具算结构化指标、RAG 提供体系依据；成果评审 Agent 用证据链和人工确认约束结论；AI Coding Harness 把任务、契约、测试和审批沉淀为可续接上下文。

### AI 全栈版

> 除了 Agent 后端，我做过 Vue3 地面站前端，处理遥测可视化、周期刷新、事件去重、用户操作与状态回填冲突；后端侧能把 FastAPI 接口、长任务状态、幂等和异常处理串起来。

### 综合版

> 我的优势是把模型能力落在明确业务边界中：结构化事实、RAG 依据、受控工具、任务状态、证据校验和人工确认各自负责，不把不确定内容包装成确定结论。

**事实边界**：轻舟是 Vue3；React 条件轮询是独立企业平台补充。评审任务确认使用后台线程，不说已用消息队列或 WebSocket。没有确认的指标、训练参数和线上规模不补充。

## 5–12 分钟：三张白板主线

```text
成果评审：checklist → 快照 → 事实 → 证据(路径/行号/SHA) → 裁决 → 无法确认/人工确认

Edge 同步：内网 GitLab → Edge → 游标增量 → SQLite Outbox → 批次发送 → 中心幂等

长任务：前端防重 → 幂等创建 → 后台执行 → 状态持久化 → 轮询/提示 → 取消/失败/中断
```

每张图各用 30 秒说清：**为什么需要它、核心控制点、一个明确边界**。

## 12–20 分钟：8 个必答题

1. **为什么不用一次 Prompt 完成评审？**
   - 节点化分离事实、证据和裁决，便于审计、重试和人工确认。
2. **怎样避免 LLM 无依据结论？**
   - 结论关联路径/行号/SHA，校验证据索引，无证据降级无法确认。
3. **结构化指标、RAG、LLM 如何分工？**
   - 指标引擎算事实，RAG 给规范依据，LLM 做受控归纳。
4. **Edge 同步如何可靠？**
   - Outbox 记待发，游标做增量，批次幂等吸收重复；至少一次而非恰好一次。
5. **状态机为何重要？**
   - 把创建、执行、待确认、取消、失败、中断变成可查询和可审计状态。
6. **轮询还是 WebSocket？**
   - 看实时性和复杂度；轻舟确认周期刷新，不宣称 WebSocket 实践。
7. **长任务如何防重？**
   - 前端防重只是体验层，服务端幂等键才是最终保障。
8. **如何回答没做过的 Infra / 训练问题？**
   - 说清未确认事实，给“目标—设计—验证”路径，不假装已上线。

## 20–27 分钟：风险扫雷

- **职责**：准确用“我负责 / 我参与 / 团队完成”。
- **指标**：论文项目有评测方法但无确认分数；红外不同配置指标不可混比。
- **技术栈**：Vue3 轻舟与 React 平台分开；后台线程、消息队列、WebSocket 分开。
- **可靠性**：Outbox + 游标 + 幂等不是恰好一次；取消是协作式，不承诺瞬时。
- **安全**：只读 GitLab Token、源码不落库、并发/文件大小限制、人工确认都是受控边界。
