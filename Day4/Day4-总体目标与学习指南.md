## 一、当天在十天计划中的位置

Day 2 说明了企业质量 Agent 如何区分结构化事实、RAG 依据和 LLM 归纳；Day 3 说明了评审 Agent 如何用固定快照和证据链约束代码评审；Day 4 转到简历中的论文引用查证智能体，重点展示我对 **检索质量、证据覆盖、结构化判定、评测闭环和无法确认降级** 的理解。

这个项目适合回答 AI 应用/Agent 岗位中的 RAG 深挖问题：文档如何解析、为什么 Hybrid RAG、如何做评测、证据不足怎么办，以及如何从错误 case 驱动迭代。

## 二、简历事实与当天边界

### 当前简历可确认的事实

- 构建基于 LLM 的论文引用查证系统，覆盖论文 PDF 解析、证据检索、引用合理性判断和结构化结果输出。
- 使用 GROBID 解析 PDF 并提取 TEI XML，完成文本切分、向量化、FAISS 检索和元数据过滤。
- 构建 Hybrid RAG：BM25 + FAISS + Rerank。
- 使用人工标注集，以 `Recall@k`、证据覆盖率和判定准确率评估检索与查证效果。
- 将解析、检索和引用验证封装为受控工具，通过 FastAPI 提供服务；结合 Redis 缓存、Docker、日志和异常处理完成工程化交付。
- 证据不足时返回“无法确认”。

### 不可擅自补充的事实

- 未发现该项目的可核验源码或项目文档；不写具体模型名称、chunk 长度、`k` 值、Rerank 模型、缓存 TTL、线上吞吐、准确率数值、部署规模或个人独立完成比例。
- “自动化回放、版本对比、失败 case 平台、人工反馈闭环”作为可继续完善的工程方案，不说成已完成系统。
