## 一、白板题：画出可信 RAG 查证链路

### 5 分钟作答顺序

1. 写输入：论文 PDF、待查引用句/上下文、目标文献。
2. 写解析：`GROBID → TEI XML → 章节/段落/参考文献/元数据`。
3. 写索引：结构化切分后同时建立 `BM25` 与 `FAISS`。
4. 写检索：查询构造与元数据过滤 → 双路召回 → 候选合并 → `Rerank`。
5. 写输出：证据组装 → 结构化判断 → 支持/部分支持/无法确认等项目定义类别。
6. 在旁边写：人工标注集 → `Recall@k` / 证据覆盖率 / 判定准确率。
7. 最后加失败分支：解析失败、无参考文献、证据不足 → 明确状态/人工查看，不强行判断。

### 参考讲解

> 我先解决“论文能不能被可靠定位地读出来”，所以用 GROBID 得到 TEI XML；再解决“正确证据能不能被找到”，所以用 BM25 和 FAISS 双路召回、Rerank 精排；最后才让模型比较引用主张和证据。评测上把召回、证据充分性和最终判断拆开看，避免只用一个准确率掩盖问题。证据不足时返回无法确认，是系统对自身检索与解析边界的诚实表达。

## 二、3 分钟口述练习

- [ ] 回答“Recall@k、证据覆盖率、判定准确率的区别”。
- [ ] 举一个证据不足时返回无法确认的例子。

## 三、错误表达修正

| 不安全表达 | 修正表达 |
| --- | --- |
| “系统能自动判断引用对不对。” | “系统基于可定位证据生成结构化辅助判断，证据不足时返回无法确认。” |
| “向量检索比 BM25 更好。” | “它们解决不同召回失败模式，组合后再通过评测比较。” |
| “Recall@k 很高所以最终结果很好。” | “Recall@k 只说明正确证据是否进候选，还要看证据覆盖和判定准确。” |
| “我把所有 PDF 问题都解决了。” | “GROBID 与异常处理覆盖了主链路；扫描件、表格、OCR 等能力需以实际实现核对。” |
| “改了 prompt 后效果明显提升。” | “只有在固定标注集和指标对比下，才能说明某项改动带来的变化。” |

## 四、事实核对清单

- [ ] GROBID 的具体部署方式、版本与个人负责范围。
- [ ] 文本切分的真实规则、chunk 参数、是否包含重叠和引用上下文拼接。
- [ ] 向量模型、Rerank 模型、索引构建方式和元数据字段。
- [ ] 人工标注集规模、标注流程、数据划分和三个指标的具体结果。
- [ ] FastAPI 路由、Redis key/TTL、Docker 配置、日志字段与实际异常处理细节。
- [ ] 是否已有 OCR、表格解析、自动回放、版本对比或人工反馈回流能力。
- [ ] 个人职责边界：我负责、我参与、团队完成分别是什么。
