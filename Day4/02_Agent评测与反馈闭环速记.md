# Agent 评测与反馈闭环速记

> **核心目标**：把“效果不错”改写成可验证的工程闭环：数据集 → 指标 → 错误 case → 修复假设 → 再次验证。

---

## 一、当前可确认的评测事实

根据当前简历，论文引用查证项目已使用**人工标注集**，并以以下指标评估检索与查证效果：

- `Recall@k`
- 证据覆盖率
- 判定准确率

这说明项目已有“不是只看模型主观回答，而是用标注数据衡量检索与结论”的基本评测意识。当前未掌握具体样本量、标注流程、指标数值、数据划分、模型对比或线上 A/B 实验记录，面试中不应补充这些细节。

## 二、评测闭环口述模板

> 我会把 RAG 优化拆成一个可验证闭环。首先准备人工标注的引用 case，明确每个 case 的引用主张、目标文献、关键证据和最终标签；然后分别看 Recall@k、证据覆盖率和判定准确率，定位问题是在召回、证据选择还是结论判断。接着保留典型失败 case，例如术语改写导致 BM25 漏召回、语义相近导致向量检索误召回、Rerank 排错或证据不足却被模型强行判断。每次改动只提出一个可验证假设，例如补充引用上下文、改元数据过滤或调整重排策略，再在固定评测集上比较变化。没有固定 case 和指标对比时，我不会仅凭几个演示例子判断方案变好了。

## 三、三层指标与定位表

| 现象 | 优先看什么 | 可能问题位置 | 可验证修复假设 |
| --- | --- | --- | --- |
| 正确段落根本没出现 | `Recall@k` | query 构造、BM25/向量索引、元数据过滤 | 加入引用上下文、优化切分或调整融合策略 |
| 候选里有正确段落，但最终证据不充分 | 证据覆盖率 | Rerank、证据组装、chunk 语义完整性 | 调整重排输入、补相邻段落或加强来源过滤 |
| 证据足够但结论错误 | 判定准确率 | 结构化判断规则、提示约束、标签定义 | 澄清标签、加入正反例、约束“无法确认”条件 |
| 解析内容混乱或缺页 | 解析成功率/失败 case（建议补充） | PDF 质量、GROBID、清洗逻辑 | 记录解析失败原因，进入 OCR/人工查看降级路径 |

> “解析成功率”是合理的后续观测指标设计，不是当前简历已披露的既有评测指标。

## 四、人工标注集如何讲

### 一个标注 case 至少应包含

- 源论文、被引论文或目标文献的稳定标识。
- 引用句与必要的相邻上下文。
- 人工认定的关键证据段落及其来源位置。
- 最终标签及标注理由。
- 无法确认 case 的原因，例如目标文献缺失、解析失败或证据不足。

### 如何避免数据泄漏

> 数据泄漏不是只指训练数据泄漏。评估中要避免同一篇论文的高度相似段落、同一引用对的改写版本同时出现在调参与测试集合，也要避免先看测试 case 的结果再针对性修改规则后仍用同一批 case 宣称泛化提升。可按论文、引用对或时间划分训练/开发/测试集合，并冻结最终测试集；具体如何划分需结合真实数据规模确认。

## 五、典型错误 case 与处理方式

### Case 1：术语改写，关键词不重合

- **现象**：引用句使用概念概括，原文使用不同表达；BM25 排名靠后或未召回。
- **定位**：词面召回不足。
- **处理假设**：引入向量召回、扩展 query 为引用句加相邻上下文、保留领域术语。
- **验证**：固定 case 上看正确证据是否进入 top-k，不能只看单次生成理由是否更流畅。

### Case 2：主题相近但不支持当前主张

- **现象**：向量检索召回“主题相关”的段落，但其中没有实验结论或因果关系。
- **定位**：语义相似被误当作证据支持。
- **处理假设**：加入 Rerank，明确 query 是“待验证主张”而不是宽泛主题；要求最终判断引用可定位段落。
- **验证**：看证据覆盖率和误支持 case 是否下降。

### Case 3：正确证据在表格、附录或解析失败区

- **现象**：正文没有可解析文本，或关键实验结果位于复杂表格中。
- **定位**：解析覆盖边界，不是模型能力不足。
- **处理假设**：显式标记解析限制，必要时增加表格/OCR 处理或人工查看路径。
- **验证**：把这类 case 独立统计，不能混进“模型判断错误”。

### Case 4：证据不足但模型强行给结论

- **现象**：候选证据不完整，模型仍说“支持”或“不支持”。
- **定位**：结构化输出约束或拒答条件不足。
- **处理假设**：要求输出证据来源与不足说明；缺少必要证据时只能返回“无法确认”。
- **验证**：检查无法确认 case 的精确性与人工复核结果。

## 六、已实现事实、可完善方案与不能说的话

| 类别 | 可以说 | 不应说 |
| --- | --- | --- |
| 已有事实 | 使用人工标注集和三个指标进行评估 | 具体数据集规模、准确率提升百分比（未核实） |
| 已有事实 | 证据不足时返回无法确认 | 已有完整线上反馈闭环或自动回放平台（未核实） |
| 可完善方案 | 固定回归集、版本对比、错误标签体系、人工修订回流 | 把方案说成已经上线运行 |
| 工程原则 | 每次改动对应明确假设，并在固定评测集上比较 | 只凭几个 demo 认为检索变好 |
