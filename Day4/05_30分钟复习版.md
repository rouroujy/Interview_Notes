# Day 4：30 分钟复习版——论文引用查证 Agent + RAG

> **目标**：只记一条可信 RAG 主线：先解析并定位文本，再检索和重排证据，最后基于证据判断；证据不够就无法确认。

## 0–5 分钟：1 分钟项目口述

> 我做过一个论文引用查证 Agent：先用 GROBID 将 PDF 解析为 TEI XML，按结构切分并建立 BM25 与 FAISS 索引；对于引用主张，用引用上下文加元数据过滤进行双路召回，再由 Rerank 精排，组装带来源的证据，最后输出结构化判断。项目使用人工标注集，以 Recall@k、证据覆盖率和判定准确率评估；证据不足时返回无法确认。工程上通过 FastAPI、Redis、Docker、日志和异常处理交付。

**事实边界**：当前只确认上述技术链路和三个评测指标；具体模型、chunk 参数、指标数值、缓存策略和线上规模不背、不猜。

## 5–12 分钟：白板关键词链

```text
PDF → GROBID → TEI XML → 章节/段落/参考文献/元数据
    → 语义切分 → BM25 + FAISS
引用句/上下文 → 查询构造 + 元数据过滤 → 双路召回 → Rerank
    → 证据组装（来源/位置） → 结构化判断 → 无法确认降级

人工标注集 → Recall@k / 证据覆盖率 / 判定准确率
```

### 画完必须说的三句

1. “PDF 先结构化，才能做可靠切分、过滤和来源定位。”
2. “BM25 补精确术语，FAISS 补语义改写，Rerank 从候选中选真正相关证据。”
3. “检索不到充分证据不等于引用错误，系统应返回无法确认。”

## 12–20 分钟：8 个必答题

### 1. 为什么不用 LLM 直接读全文？

> 上下文、定位、成本和幻觉都不可控；检索到可定位证据后再判断更可复查。

### 2. GROBID/TEI XML 的价值？

> 保留论文结构、段落和参考文献等信息，支持语义切分、元数据过滤和来源追溯。

### 3. chunk 怎么设计？

> 优先段落/章节/引用上下文；过大主题混杂，过小丢限定条件，参数通过标注集验证。

### 4. BM25、FAISS、Rerank 分别做什么？

> BM25 找术语，FAISS 找语义相近，Rerank 精排候选；三者不是替代关系。

### 5. Recall@k 是什么？

> 正确证据是否进入前 k 候选，衡量召回层；候选没找到，后面无法补救。

### 6. 证据覆盖率和判定准确率区别？

> 覆盖率看最终证据够不够，准确率看最终标签对不对；都不能由 Recall 替代。

### 7. 为什么返回无法确认？

> 解析、索引或证据本身都可能不完整；不能把系统能力边界误判成论文事实。

### 8. 发现误判如何迭代？

> 保存 case，定位在解析/召回/重排/证据/判定哪层，提出一个改动假设，再用固定标注集验证。

## 20–27 分钟：三组取舍

| 问题 | 关键回答 |
| --- | --- |
| 为什么 Hybrid RAG？ | 兼顾精确术语和语义改写，提高候选覆盖；代价是复杂度和评测成本。 |
| Rerank 为什么不直接加 top-k 替代？ | top-k 变大带来噪声，Rerank 在有限候选中提高相关性；但它无法找回未召回证据。 |
| PDF 解析失败怎么办？ | 显式返回输入/解析限制，必要时人工查看；OCR、表格解析等作为需核实的后续方向。 |
