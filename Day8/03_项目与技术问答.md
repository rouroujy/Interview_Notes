# Day 8：前端、全栈与红外动作识别问答

> 共 28 题。AI 全栈岗位优先练前 14 题；模型研究岗位优先练后 14 题。每题先给结论，再补真实项目或事实边界。

---

## 1. 请介绍轻舟货运飞船前端项目。

**答案**：这是面向航天领域地面站的遥测监控和货物辅助管理前端，使用 Vue3、Vue Router、Vuex、Axios、ECharts 和 Ant Design Vue。页面覆盖遥测表格和趋势图、摄像机预览、灯光控制、报警监控、货架可视化和操作记录，并通过周期刷新、事件去重、全局跳转与状态管理保证遥测、报警、货物和语音事件的页面一致性。

## 2. 实时刷新为什么会与用户操作冲突？

**答案**：后端状态回填可能覆盖用户正在编辑的表单、控制开关或局部查看状态，导致操作跳变和误解。解决思路是区分服务端最新状态与用户交互中的本地状态，在交互期间暂停冲突区域刷新，提交完成后再恢复并以服务端确认结果回填。

## 3. 如何设计暂停/恢复刷新？

**答案**：先定义哪些操作进入“受保护交互态”，例如编辑、控制确认或提交中；此时暂停相关模块自动回填或标记待刷新，其他无冲突模块可继续刷新。接口返回后处理成功/失败提示，结束交互态并重新拉取服务端状态。核心是按状态粒度控制，而不是全局粗暴停掉所有刷新。

## 4. 事件去重如何做？

**答案**：优先使用报警 ID、事件 ID 等稳定业务标识；没有稳定 ID 时可结合业务字段和时间窗口。去重逻辑要保证同一事件不会反复跳转、弹窗或写状态，但不能把真正的新事件误丢。具体键和窗口需以实际实现为准。

## 5. Vuex 应该放哪些状态？

**答案**：放跨页面共享、需要统一更新的状态，如报警摘要、货物状态、当前选中对象或全局事件；局部表单草稿和短生命周期 UI 状态留在组件内，避免全局状态过大和被刷新误覆盖。

## 6. Vue Router 在事件联动中如何使用？

**答案**：当报警或语音事件触发后，通过路由跳转到相应监控/控制页面，并携带对象标识或上下文；目标页面根据参数加载详情或激活对应状态。路由只负责导航，业务状态仍由状态管理和接口确认保证一致。

## 7. ECharts 遥测趋势图需要注意什么？

**答案**：要处理时间轴、采样频率、空数据、异常值、数据量和更新频率；避免每次刷新都销毁重建图表，必要时增量更新或限制展示窗口。具体优化策略要根据数据量和实际实现说明。

## 8. 为什么采用运行时配置而非构建时写死后端地址？

**答案**：不同现场/测试环境的服务地址可能不同，运行时配置让同一前端构建产物在部署时适配不同后端，减少重复打包。它不能放敏感密钥，且要处理配置加载失败。

## 9. 轮询和 WebSocket 如何选择？

**答案**：周期状态拉取可用轮询，简单且易排障；高频实时多事件可考虑 WebSocket，但要管理连接、鉴权、断线重连和资源。轻舟项目简历确认周期刷新，是否使用 WebSocket 未确认；当前企业 React 平台对活动评审任务每 3 秒条件轮询是独立代码事实。

## 10. 当前 React 企业平台如何处理长任务进度？

**答案**：代码评审页面用 React Query 查询任务列表；只要存在 queued、validating、collecting、evaluating、assembling、cancel_requested 等活动状态，就每 3 秒刷新，任务结束后停止。页面依据状态展示进度、取消、人工确认、报告下载和加载失败提示。它是企业平台补充，不是轻舟 Vue3 项目。

## 11. 前端如何处理接口失败和重复提交？

**答案**：请求期间禁用或标记提交态，失败给用户可操作的提示并保留必要输入；对创建类操作依赖后端幂等键和状态机防止网络重试产生重复副作用。前端按钮防抖只是体验层，不能替代服务端幂等。

## 12. 第三方支付或电子签名回调如何保证可靠？

**答案**：验签和校验回调来源、订单/合同状态与金额；按平台事件 ID 或业务单号幂等处理；记录处理结果；对不确定或失败状态通过主动查询、对账或人工处理补偿。简历确认有支付和电子签名对接，具体平台和协议未核实。

## 13. 如何避免用户操作与后端状态回填不一致？

**答案**：提交后不要只凭前端乐观状态判断成功，应等待接口确认；失败则回滚/提示，成功后再拉取或使用服务端返回的权威状态更新。对于并发编辑可增加版本号、更新时间或冲突提示，是否实现需按项目事实说明。

## 14. AI 全栈岗位如何串起你的前后端能力？

**答案**：我可以从页面状态与交互讲到接口契约，再到后端任务状态、轮询/推送取舍、异常提示和日志排障。轻舟体现 Vue3 实时监控交互，企业 Agent 体现 FastAPI、任务状态和审计，当前 React 平台补充了条件轮询消费任务状态；我会区分不同项目技术栈，不混为一谈。

## 15. 请介绍红外动作触发识别课题。

**答案**：课题面向封闭复杂光照环境的物资管理，完成红外视频动作触发识别，为后续多模态感知提供稳定触发信号。基于 NTU RGB-D 和 Cross-Subject 协议，采用 ResNet-18 + LSTM 基线，并设计两层红外增强、Uniform Sampling 和轻量 Temporal Attention。均匀采样方案达到 96.55% Accuracy、0.9934 AUC，综合配置达到 0.9424 F1；论文已录用，我是第一作者。

## 16. 为什么使用 Cross-Subject 协议？

**答案**：训练与测试按主体划分，测试主体不出现在训练集中，避免模型记住某些人的外观和动作习惯，更严格评估跨主体泛化。这比随机切分难度高，结果不能直接横比。

## 17. ResNet-18 + LSTM 如何分工？

**答案**：ResNet-18 提取每帧红外图像的空间视觉特征，LSTM 建模帧间时序变化和动作演化。动作识别不能只看单帧，二者组合形成空间加时间的非 Transformer 基线。

## 18. 为什么不直接使用 Transformer？

**答案**：当前工作先建立 ResNet-18 + LSTM 的非 Transformer 基线，结构成熟且适合验证红外增强、采样和时间注意力的贡献。Transformer 可能有长序列建模优势，但是否更好需要同协议对比；当前不说已实现或已优于它。

## 19. 两层红外增强解决什么？

**答案**：红外模态的视觉分布和 RGB 不同，增强的目标是提高对热分布、对比和动作轮廓的适应性，给后续特征提取提供更稳定输入。具体算子和参数需以论文/代码核对。

## 20. Uniform Sampling 为什么有用？

**答案**：不同视频长度和动作速度下，均匀采样覆盖整个动作过程，减少只看到局部片段而遗漏关键阶段的风险。它可能不擅长极短暂事件，因此采样数要结合实验评估。

## 21. Temporal Attention 的作用？

**答案**：不同时间步对动作判断贡献不同，时间注意力给关键帧更高权重，弱化冗余帧。轻量设计是在表达能力和计算开销之间取平衡。

## 22. Accuracy、AUC、F1 分别是什么？

**答案**：Accuracy 是整体正确比例；AUC 衡量不同阈值下区分正负样本的能力；F1 是 Precision 与 Recall 的调和平均，适合同时关注误检和漏检的触发任务。

## 23. 为什么不同配置的 Accuracy、AUC、F1 不能直接比大小？

**答案**：它们衡量维度不同，且当前数值来自不同实验配置。要比较优劣需要固定数据划分、类别/阈值和实验配置，再看同一指标；综合配置的 0.9424 F1 表示误检与漏检更均衡，不能直接和 96.55% Accuracy 比较。

## 24. 为什么动作识别输出是“触发信号”？

**答案**：在整体交互式感知中，触发信号可决定何时启动后续更昂贵或更针对性的感知/处理，减少无效持续计算，并为货物管理动作提供时机信息。当前完成的是触发识别，不是完整多模态目标检测闭环。

## 25. 如何处理误检和漏检的权衡？

**答案**：先明确业务代价：误检可能增加无效触发，漏检可能错过关键动作；因此不能只看 Accuracy，需要看 Precision、Recall、F1 或阈值相关指标，并在固定协议下分析。当前简历给出综合配置 F1 较均衡，但具体混淆矩阵需核实。

## 26. 如何避免训练/测试数据泄漏？

**答案**：按 Cross-Subject 协议确保测试主体不进入训练，预处理和标准化统计也应只从训练集拟合后应用到验证/测试；调参不能反复根据测试集结果修改后仍宣称泛化。具体实现流程需以实验记录核对。

## 27. 如果红外视频质量下降怎么办？

**答案**：先区分输入质量、增强、采样、空间特征还是时序建模问题，保留失败样本分析；可从增强鲁棒性、数据扩增、阈值/拒答、人工回退或多模态补充等方向设计。是否已实现这些方案必须与当前成果区分。

## 28. AI 应用与研究课题经历如何互相补强？

**答案**：研究课题证明我能进行任务定义、数据划分、模型设计和指标评估；Agent 项目证明我能把模型放进数据、工具、接口、证据与人审边界内交付。投应用岗位时以工程项目为主、研究为补充；投模型研究岗位时以课题为主、Agent 的评测与工程化作为加分项。
