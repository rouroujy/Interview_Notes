## 二、Agent / AI Coding 岗

### 推荐项目顺序

1. **AI Coding Harness**：工程上下文、接口契约、测试计划、人工审批。
2. **成果评审 Agent**：工作流、证据校验、长任务状态和安全边界。
3. **质量管理体系 Agent**：受控工具、结构化事实/RAG/LLM 分工、Edge 同步。
4. **论文引用查证**：RAG 评测与证据不足降级，作为检索能力补充。

### 90 秒开场主线

> 我的重点是把 LLM 能力做成受控、可追溯的工程流程。AI Coding Harness 解决的是 AI 开发时的上下文与人工审批；成果评审 Agent 解决的是代码评审结论必须有证据；质量管理体系 Agent 解决的是结构化数据、规范依据和内网数据接入的边界。我会优先保证事实、工具权限、任务状态和人工确认可控，再讨论模型生成能力。

### 预判追问

- Context Engineering 如何避免上下文过期或冲突？
- 证据索引校验是怎样把 LLM 结论约束住的？
- 多 Agent、MCP、向量库为什么不是默认选项？
- 评审任务取消、重启、超时和重试如何设计？

### 主动边界

- Harness 是受控开发框架，不是自动上线系统。
- 评审任务确认后台线程和有界并发，不说消息队列、K8s 或生产高并发平台。

## 三、RAG / AI 应用岗

### 推荐项目顺序

1. **论文引用查证 Agent**：PDF 解析、Hybrid RAG、评测和证据不足降级。
2. **质量管理体系 Agent**：结构化计算与 RAG 文档依据的分工。
3. **成果评审 Agent**：证据链和人工确认，证明 RAG/LLM 输出可以受控进入业务流程。

### 90 秒开场主线

> 我做 RAG 时更关注检索和业务结论之间能否建立证据链。论文引用查证项目从 GROBID 解析到 Hybrid RAG，再用人工标注集评估 Recall@k、证据覆盖率和判定准确率；质量 Agent 中，我把确定性指标交给工具计算、把质量体系文档交给 RAG、再让 LLM 做归纳，避免模型替代事实计算。我的习惯是证据不足时明确降级，而不是追求看上去完整的回答。

### 预判追问

- BM25、向量检索和 Rerank 的互补关系？
- 如何构建评测集并定位问题在解析、召回、排序还是生成？
- 结构化查询和 RAG 的边界？
- 知识更新、缓存与权限如何处理？

### 主动边界

- 论文项目有评测方法，但未确认的具体分数不补充。
- Redis 确认用于缓存，具体 key、TTL 和失效策略必须以代码核对。

## 四、AI 全栈岗

### 推荐项目顺序

1. **成果评审 / 质量 Agent**：FastAPI、任务状态、幂等、异常和工程协作。
2. **后端工程化映射**：MySQL、SQLAlchemy、Alembic、Redis、Docker、Outbox 等按真实项目落点解释。
3. **轻舟货运飞船前端**：Vue3、遥测可视化、周期刷新、事件去重、暂停/恢复刷新、运行时配置。
4. **旧全栈经历**：第三方接口可靠性的一般思路，只在被追问时讲且不补未核实细节。

### 90 秒开场主线

> 我的 AI 全栈理解是从页面状态到后端任务状态形成一个可排障的闭环。前端上，我在轻舟 Vue3 项目中做遥测可视化、周期刷新、事件去重，以及用户操作期间暂停/恢复刷新；后端上，我在 Agent 项目里处理 FastAPI 接口、任务状态、幂等、取消/重试和日志异常。遇到长任务时，创建请求不阻塞，状态独立持久化，前端根据状态做轮询或提示；我能说明 WebSocket 的适用场景，但不会把它说成轻舟既有实现。

### 预判追问

- 用户编辑和周期刷新如何避免互相覆盖？
- 轮询和 WebSocket 怎么取舍？
- 幂等键、状态机、后台任务如何协作？
- Edge 同步中如何处理网络失败和重复投递？

### 主动边界

- 轻舟技术栈是 Vue3/Vuex/ECharts；React 条件轮询是独立企业平台补充。
- 当前确认后台线程，不说已经使用消息队列或分布式 worker。

## 五、模型研究 / 训练岗

### 推荐项目顺序

1. **红外动作触发识别**：问题定义、Cross-Subject、ResNet-18 + LSTM、三项设计、指标和局限。
2. **LLM / Transformer 理论基础**：根据 JD 准备自注意力、微调、评测等基础；明确是理论补齐还是实践经验。
3. **Agent 应用项目**：强调将模型能力工程化、可评测和安全降级的能力。

### 90 秒开场主线

> 我的研究课题面向复杂光照下的红外动作触发识别，目标是为后续多模态物资管理提供稳定触发信号。我在 NTU RGB-D 的 Cross-Subject 协议下，用 ResNet-18 提取帧级空间特征、LSTM 建模时序关系，并设计两层红外增强、Uniform Sampling 和轻量 Temporal Attention。均匀采样配置达到 96.55% Accuracy、0.9934 AUC，综合配置达到 0.9424 F1；这些来自不同配置和指标，不能直接做数值大小比较。我的经验更集中在该课题的训练/评估与 AI 应用工程，不会把 LLM 微调、RL 或训练集群包装成已完成项目。

### 预判追问

- Cross-Subject 验证什么泛化能力？如何防数据泄漏？
- 为什么选择 ResNet-18 + LSTM 而不是 Transformer？
- Accuracy、AUC、F1 的适用场景和可比性？
- 如果模型要上线，如何处理误检、漏检、数据漂移和资源限制？

### 主动边界

- 不虚构超参数、类别表现、硬件、训练轮数或完整多模态闭环。
- LLM 微调、RL 和训练框架按知识边界回答，不冒充真实项目经验。

## 六、反问问题库（选 2–3 个）

### 产品与业务

- 团队当前的 Agent 或 AI 产品主要服务哪些业务流程？模型输出通常如何进入人工或系统决策？
- 当前最棘手的业务约束是数据质量、权限、时效性，还是用户对结果可信度的要求？

### 评测与工程

- 团队有怎样的离线评测、线上观测和反馈闭环？最关注哪些质量或稳定性指标？
- 在数据权限、敏感信息和外部工具调用上，团队通常如何设置边界和审计？

### 岗位成长

- 这个岗位入职后 3–6 个月最希望新人独立承担的模块或交付是什么？
- 团队如何安排代码评审、技术复盘和跨角色协作，帮助新人提升工程能力？

### 反问使用规则

- 不问官网或 JD 已明确写出的内容。
- 面试官已经回答的内容不重复问；可顺着对方技术方案追问一层。
- 优先问与你实际关心的业务边界、评测和成长机制相关的问题，不在首次面试过早只问福利。
