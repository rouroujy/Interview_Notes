# Day 7：算法与计算机基础集中补强

> **当天主题**：用“题型识别 → 数据结构 → 不变量 → 复杂度 → 边界”的方法应对算法题，并把网络、操作系统基础映射回 Agent 长任务、接口、鉴权和并发场景。

> **阅读顺序**：先读本文件，再读 `01_算法错题与模板.md`、`02_计算机基础速记.md`、`03_练习与验收.md`，最后用 `04_30分钟复习版.md`。

---

## 一、当天在十天计划中的位置

Day 1–Day 6 已完成项目、LLM/RAG 与后端工程材料。Day 7 不新增简历项目，而是补齐技术面常见基础题，避免在项目讲得清楚后被算法、HTTP、并发或操作系统追问打断节奏。

今天的原则是：

> 算法题先说思路、复杂度和边界，再写代码；基础题先说定义和取舍，再关联项目，绝不把通用方案说成已经上线的项目能力。

## 二、项目关联与事实边界

| 基础主题 | 可关联项目场景 | 不能夸大的部分 |
| --- | --- | --- |
| 线程/协程/I/O | 代码评审长任务、GitLab/LLM 外部调用、Edge 同步 | 不说已完成高并发分布式调度 |
| HTTP/HTTPS | FastAPI 接口、Edge 主动同步、GitLab/禅道 API 调用 | 不说已完成完整网关/零信任平台 |
| 鉴权与 CORS | 企业内部 API、只读 GitLab Token、前后端跨域 | 具体 JWT/Cookie 实现需以代码核对 |
| WebSocket/轮询 | 长任务进度查询与前端状态展示 | 当前只确认状态查询、进度和审计；是否使用 WebSocket 未确认 |
| 进程/线程/死锁 | 后台任务、有界并发、协作式取消 | 不说已处理所有死锁或实现进程池 |
| 算法 | 通用编码与问题拆解能力 | 不把刷题成果包装成业务项目成果 |

## 三、当天能力目标

- 能对数组/哈希、双指针、滑动窗口、栈队列、链表、树、二分、DFS/BFS、回溯、动态规划各说出一个识别模板。
- 能先给出时间/空间复杂度，再说明边界条件和不变量。
- 能解释 HTTP、HTTPS/TLS、TCP、Cookie/Session/JWT、WebSocket、CORS 的基础和工程取舍。
- 能解释进程、线程、协程、死锁、I/O 密集与 CPU 密集任务的选择。
- 能将网络/并发知识关联到 Agent 长任务、取消、鉴权、轮询和 Edge 同步。
- 能明确区分已实现的有界并发、幂等、隔离与尚未确认的高并发分布式能力。
